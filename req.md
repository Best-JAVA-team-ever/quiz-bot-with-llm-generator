# Quiz Bot with LLM Question Generator. Требования



## 1. Введение



**Quiz Bot with LLM Question Generator** - это Telegram-бот для обучения, который позволяет создавать викторины как вручную, так и с помощью генерации вопросов при помощи LLM. Бот автоматически проверяет ответы пользователя, предоставляет развернутые пояснения к ошибкам, а также анализирует историю ответов для формирования персональной статистики и адаптивной подборки вопросов с учетом ранее данных ответов.



---



## 2. Функциональные требования



### 2.1. Общие для всех пользователей



#### 2.1.1. Роли

- **Admin** - администратор;

- **Respondent** - респондент;



#### 2.1.2. Авторизация

- Авторизация и все дальнейшее взаимодействие с ботом реализовано через Telegram. При первом взаимодействии с ботом сохраняется его ID для дальнейшего сохранения полученных данных в системе. По умолчанию все пользователи являются респондентами. 

- Для того чтобы перейти от респондента к администратору, нужно ввести команду `\become admin <Пароль>`. При переходе вся статистика респондента сохраняется;

- Для того чтобы перейти от администратора к респонденту, нужно ввести команду `\become respondent`;



#### 2.1.3. Вывод базы вопросов

- Пользователь имеет возможность вывести список всех вопросов.

  - Для **Администратора** : 

    - При вызове команды `\get questions` выводится список всех тем, существующих на данный момент в системе вместе с количеством вопросов, которые затрагивают данные темы;   

    - При вызове команд `\get questions all` и `\get questions <Название темы>` выводится список вопросов вместе с их ID, сложностью, правильным ответом, списком неправильных ответов и темами, которые они затрагивают. В случае `all` список затрагивает все вопросы в системе и к каждому вопросу добавляются темы. В случае `<Название темы>` выводится список вопросов, которые покрывают определенную тему;

  - Для **Респондента** : 

    - При вызове команды `\get questions` выводится список всех тем вместе с количеством вопросов, которые затрагивают данные темы и количеством вопросов, на которые был дан корректный ответ; 

    - При попытке добавления параметров `all` и `<Название темы>` к вызову выводится сообщение `Недоступная команда`;



#### 2.1.4. Вывод команд

- Пользователь имеет возможность получить информацию обо всех командах, доступных для его роли, при помощи команды `\help`.

  

### 2.2. Администратор



#### 2.2.1. Добавление новых тем

- Администратор имеет возможность добавлять новые темы при помощи вызова команды `\add tag <Название темы>`. 

  - Если `<Название темы>` уже существует, то выводится сообщение `Тема <Название темы> уже существует`;

  - Если `<Название темы>` некорректна, то выводится сообщение `Тема <Название темы> некорректна`;

  - В противном случае выводится сообщение `Тема <Название темы> добавлена` и тема добавляется;

- Тема является корректной, если:

  - Текст удовлетворяет следующему регулярному выражению `^[а-яА-Яa-zA-Z0-9\s\.,!?;:\-\"\'()]{4,25}$`;

  - Текст не равен `all`;



#### 2.2.2. Добавление новых вопросов

##### 2.2.2.1. Добавление нового вопроса вручную

- Администратор имеет возможность добавлять новые вопросы следующим образом:

  1. Процесс добавления вопроса начинается с отправки команды `\add question <Название темы 1> <Название темы 2>`, которая принимает неограниченное число тем. В случае если введенная тема не присутствует в базе, то она добавляется автоматически и выводится сообщение `Добавлена новая тема <Название темы>`;

  2. Система отправляет сообщение `Введите текст вопроса:`. Пользователь должен ввести текст вопроса;

  3. Система отправляет сообщение `Введите текст правильного ответа:`. Пользователь должен ввести текст ответа;

  4. Система отправляет сообщение `Введите текст неправильного ответа i:` для каждого из 3 неверных ответов. Пользователь должен ввести для них текст;

  5. Система отправляет сообщение `Выберите уровень сложности вопроса:`, с опциями выбора в виде кнопок, имеющих значение от 1 до 5. При нажатии на кнопку сообщение заменяется на `Выбрана сложность <Уровень сложности>`;

  6. Ввод вопроса завершается и выводится сообщение `Вопрос успешно добавлен под идентификатором <ID>`;

  - Все шаги пользовательского ввода сопровождаются проверкой корректности введённых данных. В случае некорректного ввода прерывается процесс добавления вопроса и выводится сообщение в виде `Прервано добавление вопроса по причине: <Описание причины>`. 

    - Вопрос является корректным, если его текст удовлетворяет регулярному выражению<br>`^[а-яА-Яa-zA-Z0-9\s\.,!?;:\-\"\'()]{10,50}$`;

    - Ответ является корректным, если его текст удовлетворяет регулярному выражению<br>`^[а-яА-Яa-zA-Z0-9\s\.,!?;:\-\"\'()]{4,25}$`;

##### 2.2.2.2. Добавление нового вопроса при помощи генерации

- Администратор имеет возможность добавлять новые вопросы при помощи генерации, реализуемой при помощи LLM, следующим образом:

  - В случае прерывания генерации выводится сообщение `Генерация прервана`;

  1. - При вызове команды `\add question gen` случайным образом выбирается уровень сложности и названия тем из списка существующих. Если в системе нет тем, выводится сообщение `В системе нет ни одной темы` и процесс генерации прерывается;

     - При вызове команды `\add question gen <Название темы 1> <Название темы 2>...` в случае некорректного ввода параметров выводятся следующие сообщения, текст которых соответствует причине: `<Название темы> - некорректное название темы`, `Не было введено название темы`, и генерация вопроса прекращается. При корректном вводе команды выводится сообщение `Выберите уровень сложности`, с кнопками для выбора значения, которое при нажатии заменяется на `Выбрана сложность <Уровень сложности>`;

  2. Выводится сообщение `Генерация вопроса по теме(ам) <Название темы1> <Название темы2>... с уровнем сложности <Уровень сложности>`;

  3. В случае если генерация вопроса превышает допустимое время, выводится сообщение `Время генерации превысило допустимое значение. Продолжить генерацию?`, с кнопками `Да` и `Нет`;

      - При нажатии `Да` генерация продолжается. Если вновь проходит предельное значение времени генерации, то предложение снова выводится;

      - При нажатии `Нет` кнопки с сообщения пропадают и генерация прекращается;

  4. При некорректном выводе со стороны LLM после генерации (тот, который не удается распарсить по значениям вопроса и ответов) система совершает повторный запрос до того момента, пока не будет превышен предел суммарного значения использования токенов для генерации одного вопроса. В случае если данное значение оказалось превышено, выводится сообщение `Сумма токенов для генерации превышена` и генерация прерывается;

  5. Генерация вопроса завершается и выводится сообщение `Вопрос успешно сгенерирован\nВопрос: <Текст вопроса>\nПравильный ответ: <Текст правильного ответа>\nНеправильные ответы: <Текст неправильных ответов>`;

#### 2.2.2.3. LLM-подсказки для сложных вопросов

- Во время прохождения викторины респондент имеет возможность запросить подсказку к текущему вопросу при помощи кнопки `Подсказка`, отображаемой вместе с вариантами ответа;

- При нажатии система обращается к LLM с запросом на формирование наводящей подсказки, не раскрывающей правильного ответа напрямую. Пока идёт запрос, отображается сообщение `Генерирую подсказку...`;

- Сформированная подсказка выводится отдельным сообщением. Запрос подсказки не влияет на счёт и статистику пользователя;

- В случае ошибки обращения к LLM выводится сообщение `Не удалось получить подсказку: <Причина>`;



#### 2.2.3. Обновление вопроса

- Администратор имеет возможность обновить существующий вопрос при помощи команды `\update question <ID>`.

  - В случае если вопрос с указанным `<ID>` не найден, выводится сообщение `Вопрос с таким ID не существует`;

  - При нахождении вопроса система последовательно предлагает изменить каждое поле (текст вопроса, правильный ответ, неправильные ответы, уровень сложности, темы), отображая текущее значение. Для каждого поля выводятся кнопки `Изменить` и `Оставить без изменений`;

  - Ввод новых значений сопровождается теми же проверками корректности, что и при добавлении вопроса (§2.2.2.1);

  - По завершении процесса выводится сообщение `Вопрос <ID> успешно обновлён`;



#### 2.2.4. Удаление темы

- Администратор имеет возможность удалить тему при помощи команды `\delete tag <Название темы>` в случае если по данной теме нет вопросов. В противном случае выводится соответствующее сообщение;



#### 2.2.5. Удаление вопроса

  - Администратор имеет возможность удалить любой вопрос, используя команду `\delete question <ID>`. В случае если в системе не найден вопрос с ID = `<ID>`, выводится сообщение `Вопрос с таким ID не существует`;

  - Администратор имеет возможность удалить все вопросы по теме командой `\delete question <Название темы>`. В случае если в системе не найдена тема с названием `<Название темы>`, выводится сообщение `Данной темы не существует`;

  - Администратор имеет возможность удалить все вопросы командой `\delete question all`;

  - При удалении вопросов по теме или всех вопросов после вызова команды администратор получает сообщение `Вы уверены?`, c кнопками `Да` и `Нет`, которое при нажатии изменяется соответственно на `Вопросы удалены` или `Удаление отменено`;



#### 2.2.6. Управление расписанием автоматической отправки вопросов

- Администратор имеет возможность настроить автоматическую отправку случайного вопроса всем активным респондентам по расписанию.

  - При вызове команды `\schedule set <cron-выражение>` устанавливается расписание автоматической отправки. В случае некорректного cron-выражения выводится сообщение `Некорректное cron-выражение`;

  - При вызове команды `\schedule set <cron-выражение> <Название темы>` автоматическая отправка ограничивается вопросами из указанной темы. В случае если тема не найдена, выводится сообщение `Темы <Название темы> не существует`;

  - При вызове команды `\schedule off` расписание отключается и выводится сообщение `Автоматическая отправка отключена`;

  - При вызове команды `\schedule status` отображается текущее состояние расписания: активно/отключено, установленное cron-выражение и тема (если задана);

- По наступлении времени по расписанию каждому активному респонденту отправляется случайный вопрос в соответствии с логикой выбора, описанной в §2.3.2;

#### 2.2.7. Управление группами

- Администратор имеет возможность создать группу при помощи команды `\group create <Название группы>`. При успешном создании выводится сообщение `Группа <Название группы> создана` и генерируется уникальная ссылка-приглашение;

- При вызове команды `\group invite <Название группы>` генерируется или повторно отображается ссылка-приглашение для вступления в группу;

- Любой пользователь может вступить в группу, перейдя по ссылке-приглашению. При вступлении выводится сообщение `Вы вступили в группу <Название группы>`;

- При вызове команды `\group list` выводится список всех групп, в которых состоит пользователь;

- Администратор имеет возможность удалить группу при помощи команды `\group delete <Название группы>` с запросом подтверждения;



#### 2.2.8. Групповой счёт

- При вызове команды `\group score <Название группы>` выводится таблица счёта участников группы, отсортированная по убыванию процента правильных ответов. Для каждого участника отображается имя пользователя, количество отвеченных вопросов и процент правильных ответов;

- Групповой счёт ведётся отдельно от персонального и не синхронизируется с ним;



#### 2.2.9. Групповые вопросы по расписанию

- Администратор имеет возможность настроить автоматическую отправку вопросов в контексте группы при помощи команды `\group schedule set <Название группы> <cron-выражение>`;

- По наступлении времени по расписанию каждому участнику группы отправляется один случайный вопрос, выбранный из общего пула вопросов всех участников группы в соответствии с логикой выбора, описанной в §2.3.2;

- Отключение группового расписания осуществляется командой `\group schedule off <Название группы>`;




### 2.3. Респондент

 

#### 2.3.1 Запуск викторины

- Респондент имеет возможность запустить викторину по всем вопросам в системе командой `\quiz start`; 

- Респондент имеет возможность запустить викторину по всем вопросам в системе с определёнными темами командой `\quiz start <Название темы 1> <Название темы 2>...`. В случае если введённой темы не существует, выводится сообщение `Темы <Название темы> не существует`;

- В дальнейшем под понятием викторины подразумевается как викторина по всем вопросам системы, так и по определённым темам;



#### 2.3.2 Прохождение викторины

- **Логика проведения викторины** - После каждого полученного ответа в базе данных создается экземпляр ответа, основными полями которого являются ID вопроса, ID респондента, значение ответа и дата с временем, когда был дан ответ. При выборе системой очередного вопроса должна быть реализована следующая логика на основе запросов к базе данных: 

  - Вопросы сортируются по уровню сложности (лёгкие идут вперёд);

  - Вопросы сортируются по дате и времени ответа (вопросы, которые задавались более давно или вообще не задавались, идут вперёд);

  - Вопросы, на которые уже даны верные ответы, отбрасываются (случай, когда на все вопросы дан корректный ответ, приравнивается к отсутствию вопросов);

  - Имеет место незначительная случайная перестановка ближайших вопросов для исключения цикличных последовательностей задания вопросов;

1. После запуска викторины респондент получает сообщение, в котором содержатся названия тем, текст вопроса и варианты ответа в виде кнопок;

    - При нажатии на правильный ответ сообщение заменяется на `Ответ корректный` и прохождение викторины продолжается; 

    - При нажатии на неверный ответ сообщение заменяется на `Ответ некорректный\nКорректный ответ: <Правильный ответ>`, к которому прикреплены кнопки `Ок` и `Объяснить`;

      - При нажатии `Ок` сообщение заменяется на `Ответ некорректный` и викторина продолжается;

      - При нажатии `Объяснить` система обращается к LLM с запросом на развёрнутое пояснение правильного ответа в контексте заданного вопроса. Пока идёт обращение к LLM, отображается сообщение `Получаю объяснение...`. После получения ответа от LLM пояснение выводится отдельным сообщением, после чего викторина продолжается. В случае ошибки обращения к LLM выводится сообщение `Не удалось получить объяснение: <Причина>`;

2. - В случае если в системе больше нет вопросов, выводится сообщение `Нет неотвеченных вопросов`;

   - Процесс повторяется до того момента, пока респондент не введёт любую текстовую команду. При завершении викторины выводится сообщение `Викторина окончена`;



#### 2.3.3 Просмотр счёта и статистики

- Респондент имеет возможность просмотреть свой общий счёт при помощи команды `\score`. Выводится сообщение, содержащее:

  - Общее количество отвеченных вопросов;

  - Количество правильных и неправильных ответов;

  - Процент правильных ответов;

- Респондент имеет возможность просмотреть счёт в разрезе тем при помощи команды `\score <Название темы>`. Выводится сообщение, содержащее аналогичные показатели, ограниченные вопросами указанной темы. В случае если тема не найдена, выводится сообщение `Темы <Название темы> не существует`;

- Респондент имеет возможность сбросить свой счёт до нуля при помощи команды `\score reset`. После вызова команды выводится запрос подтверждения `Вы уверены? Весь прогресс будет удалён`, с кнопками `Да` и `Нет`;

  - При нажатии `Да` вся история ответов респондента удаляется и выводится сообщение `Счёт сброшен`;

  - При нажатии `Нет` операция отменяется и выводится сообщение `Сброс отменён`;

- Респондент имеет возможность просмотреть детальную статистику по вопросам в рамках темы при помощи команды `\stat <Название темы>`. Выводится сообщение, содержащее текст всех вопросов, на которые респондент давал ответ, значение последнего ответа, значение правильного ответа; в случае, если был получен правильный ответ, то выводится также номер попытки, с которой данный ответ был получен.



### 2.4. Необрабатываемые запросы

- Система обрабатывает команды и текстовый ввод строго в последовательности, описанной в Пунктах 2.2. и 2.3.;

- Система не обрабатывает любые другие форматы запроса (картинки, голосовые файлы и файлы любых других форматов) и при попытке выводит сообщение `Некорректный формат сообщения`. Система не обрабатывает неподдерживаемые команды и текстовый ввод в моменты, когда не было передано приглашение к текстовому вводу;

## 3. Нефункциональные требования



### 3.1. Производительность

- Время ответа бота на команду (без учёта обращения к LLM) не должно превышать 2 секунды;

- Предельным значением генерации вопроса при помощи LLM является 20 секунд. После прохождения данного порога пользователь получает сообщение с предложением приостановить генерацию. В случае продолжения система высылает предложения остановить генерацию каждые 20 секунд;

- Предельное суммарное значение токенов, используемых для генерации вопроса, равно 1000. При превышении данного значения генерация прекращается;

- Система должна выдерживать не менее 20 одновременных активных пользователей;



### 3.2. Надёжность и доступность

- Доступность сервиса – не ниже 99.0%;

- При сбое внешнего LLM-сервиса система должна корректно обрабатывать ошибки и возвращать пользователю сообщение с описанием причины отсутствия возможности воспользоваться сервисом;



### 3.3. Безопасность

- Взаимодействие с платформой мессенджера должно происходить по HTTPS;

- Ключи API для LLM и других внешних сервисов, токен телеграм-бота и пароль для перехода к роли администратора должны храниться в защищённом виде (переменные окружения, секретные хранилища);

- Все пользовательские данные и история ответов должны быть доступны только владельцу;



### 3.4. Масштабируемость

- Архитектура должна позволять горизонтальное масштабирование компонентов, работающих с БД и очередями;

- Вызовы LLM должны быть вынесены в отдельный асинхронный сервис или очередь, чтобы не блокировать основной поток обработки сообщений;



### 3.5. Логирование и мониторинг

- Все действия по изменению данных (добавление/удаление вопросов, тем) должны логироваться с указанием инициатора и времени;

- Должен вестись мониторинг использования LLM API (количество запросов, задержки, ошибки);

## 4. Допущения и ограничения



### • Внешний LLM API

- Для генерации вопросов используется внешний LLM-сервис;

- При исчерпании квот или сбоях API пользователю возвращается сообщение;

- Для защиты от превышения лимитов запросы к LLM ставятся в очередь с регулировкой частоты;



### • Качество генерируемого контента

- Сгенерированные LLM вопросы могут содержать фактические неточности. Система не гарантирует абсолютную достоверность контента.



### • Ограничения данных

- Групповой счёт ведётся отдельно от персонального и не синхронизируется с ним.
